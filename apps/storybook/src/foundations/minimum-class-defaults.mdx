# Minimum-class defaults

Every Tier 3 **host** (`.eevenkoto-<component>`) must look and behave as the **documented default** with no modifier classes. Modifiers are only for departing from that default. Framework `*ClassNames()` helpers may still emit explicit default aliases (`--primary`, `--md`, …) for a stable prop API.

Also read: [Tier 3 — Component Scoping](?path=/docs/foundations-color-tokens-tier-3-component-scoping--docs) · [Typography](?path=/docs/foundations-typography--docs) · [Packages](?path=/docs/foundations-packages--docs) · [AGENTS.md](/AGENTS.md)

## Rules for authors

1. **Host = default.** Put the full default recipe (colors, size, interactive states, elevation) on `.eevenkoto-<block>`, via private-bridge fallbacks and host-level state selectors where needed.
2. **Modifiers are opt-in.** `--secondary`, `--sm`, `--solid`, etc. only change what is not already the default.
3. **Default modifier classes are aliases.** `--primary`, `--md`, `--subtle`, `--text`, `--stripe-row` may exist for helpers/docs but must not be *required* for the default look.
4. **Tag inference (type only).** Heading levels may come from `:where(hN).eevenkoto-heading` (zero tag specificity so `--M` still overrides). Do not use bare global `h1` / `p` / `button` selectors.
5. **Prose vs Flow.** Bare `h1`–`h6` / `p` / `ul` / `ol` / `li` get type styles only under `.eevenkoto-prose`. Vertical rhythm stays on `.eevenkoto-flow`. Compose: `eevenkoto-prose eevenkoto-flow`.
6. **Helpers may still be explicit.** Core can emit default modifiers so Button / Paragraph / List / Badge size props stay aligned; CSS must not depend on those classes for the default.

## Checklist when adding or changing a component

- [ ] `.eevenkoto-<block>` alone matches the Storybook default canvas
- [ ] Hover / focus / active / disabled for the default variant work without the default variant class
- [ ] Non-default variants fully override host defaults (no leaked primary hover, etc.)
- [ ] Docs show minimum markup (`class="eevenkoto-button"`, not only the fully expanded class list)
- [ ] If introducing “none” / opt-out (e.g. table stripe), emit an explicit modifier (`--stripe-none`) rather than relying on absence of a required default class

## Current defaults (hand-authored minimum)

| Host | Minimum markup | Default meaning |
| --- | --- | --- |
| Heading | `<h2 class="eevenkoto-heading">` | Level from tag (`:where(hN)`); `--M` overrides |
| Paragraph | `<p class="eevenkoto-paragraph">` | `body-md` + primary |
| List | `<ul class="eevenkoto-list">` + bare `li` | unordered + `body-md` + primary (`ol` / `--ordered` for decimal); items via host descendants |
| Button | `<button class="eevenkoto-button">` | primary + md (full states) |
| Badge | `<span class="eevenkoto-badge">` | subtle + neutral + md + pill |
| Badge intent | `eevenkoto-badge eevenkoto-badge--success` | subtle + that intent |
| Badge surface | `eevenkoto-badge eevenkoto-badge--solid` | solid + neutral |
| Table | `<table class="eevenkoto-table">` | default variant + row stripe |
| TableCell | `<td class="eevenkoto-table-cell">` | text kind |
| Prose | `<div class="eevenkoto-prose">` + bare `h*` / `p` / `ul` / `ol` / `li` | same defaults as classed type |
| Flow | Compose with Prose for bare-tag pair gaps | classed primitives always |

## CSS patterns

### Host carries default tokens and states

```css
.eevenkoto-button {
  --_eevenkoto-button-text: var(
    --eevenkoto-button-text,
    var(--eevenkoto-color-control-primary-text)
  );
  /* … full primary + md fallbacks, including elevation … */
}

/* Default interactive states on the host; exclude non-default variants */
.eevenkoto-button:hover:not(.eevenkoto-button--secondary):not(.eevenkoto-button--ghost) {
  /* primary hover publics */
}

.eevenkoto-button--primary {
  /* optional explicit alias — same publics as host defaults */
}
```

### Tag maps with `:where` (Heading)

```css
:where(h1).eevenkoto-heading,
.eevenkoto-heading--1,
.eevenkoto-prose :where(h1) {
  /* level 1 publics */
}
```

`:where` keeps tag specificity at 0 so `.eevenkoto-heading--3` wins on `h1.eevenkoto-heading.eevenkoto-heading--3`.

### Intent / variant shortcuts (Badge)

Put the **default surface** recipe on intent-only classes; higher-specificity compounds cover non-default surfaces:

```css
.eevenkoto-badge--success { /* subtle success */ }
.eevenkoto-badge--solid { /* solid neutral */ }
.eevenkoto-badge--solid.eevenkoto-badge--success { /* solid success */ }
```

## Anti-patterns

- Requiring `--primary` / `--md` / `--subtle` / `--default` for the default look
- Putting default hover only on `.eevenkoto-button--primary:hover` so host-alone buttons look dead
- Bare `h1 { … }` or `button { … }` outside Prose / host compounds
- Treating Flow as a substitute for Prose (Flow owns gaps; Prose owns bare-tag type)
