# Glossary

Canonical vocabulary for Eevenkoto APIs, source layout, and docs. Prefer these names in props, types, file paths, and prose.

Also read: [Component taxonomy](?path=/docs/foundations-component-taxonomy--docs) · [Authoring composed components](?path=/docs/foundations-authoring-composed-components--docs) · [Minimum-class defaults](?path=/docs/foundations-minimum-class-defaults--docs) · [Packages](?path=/docs/foundations-packages--docs) (Button vs LinkButton chooser for agents)

## Locale policy

- **Public APIs are English** (prop names, type names, BEM blocks, defaults).
- **Product-language strings are data** — Finnish (or any locale) belongs in story / app props, not in `@eevenkoto/core`.
- English defaults (`Score`, `Modifier`, `Save`, `proficient`) may ship for AT labels; override them when the surrounding UI is localized (`scoreLabel`, `modifierLabel`, `saveLabel`, `proficientLabel`).

## Architecture terms

| Term | Meaning |
| --- | --- |
| **Core** | Product-agnostic chrome; no RPG vocabulary required |
| **Domain** | Eevenkoto content patterns (creatures, abilities, statblocks); may compose Core |
| **Atom** | One semantic unit + BEM classes |
| **Molecule** | Layout of atoms + local ARIA |
| **Organism** | Page-shaped composition, slots, outline |
| **Tier 1 / 2 / 3** | Token layers: primitives → semantics → component bridges |
| **Host default** | `.eevenkoto-<block>` alone = documented default look; see [Minimum-class defaults](?path=/docs/foundations-minimum-class-defaults--docs) |
| **Prose** | Scope for bare `h1`–`h6` / `p` / `ul` / `ol` / `li` / `hr` / `blockquote` / `dl` / `a` type styles (excludes `eevenkoto-*` classes; compose with Flow for rhythm) |
| **Flow** | Vertical rhythm (`margin-block-start`) for stacked primitives, boxed blocks, and Prose+Flow bare tags |

## Domain entry stack

| Term | Meaning | Prop / type |
| --- | --- | --- |
| **Statblock** | Creature / entity **entry** organism | `StatblockProps` |
| **name** | Creature title | `name`, `nameLevel` |
| **flavor** | Optional lead paragraph | `flavor` |
| **typeLine** | Size / type caption | `typeLine` |
| **vitals** | Combat vitals PropertyList (AbilityScoreGroup **header**) | `vitals: PropertyItem[]` |
| **abilities** | Ability columns | `abilities: AbilityScoreProps[]` |
| **details** | Skills, gear, senses, languages, CR (AbilityScoreGroup **footer**) | `details: PropertyItem[]` |
| **section** | Named block (Actions, Reactions, …) | `StatblockSectionProps.title` |
| **feature** | Named action / trait / reaction line | `StatblockFeatureProps` (`name`, `description`) |
| **AbilityScore** | One ability column (label + score + modifier + save) | `AbilityScoreProps` |
| **AbilityScoreGroup** | Sandwich organism (header + grid + footer) | `AbilityScoreGroupProps` |

Do **not** use **traits** for the footer PropertyList — that word collides with feature-style “traits” in rules prose. The footer rail is **`details`**.

## Domain spell entry

| Term | Meaning | Prop / type |
| --- | --- | --- |
| **Spellblock** | Spell **entry** organism (banded card) | `SpellblockProps` |
| **typeLine** | Level + school line, italic on the title plate | `typeLine` |
| **classes** | Optional catalog rail (classes that grant the spell) | `classes: PropertyItem[]` |
| **properties** | Casting time, range, components, duration — the boxed stat band | `properties: PropertyItem[]` |
| **paragraphs** | Effect prose, one entry per paragraph | `paragraphs` |
| **features** | Scaling entries (higher-level slot, cantrip upgrade) | `StatblockFeatureProps[]` |
| **deck** | Compact card variant for spell grids | `deck` |

Spellblock reuses **StatblockFeature** for scaling run-ins; there is no separate spell-feature molecule. Spell entries have no named **sections** — 5.5e prints no section title inside a spell, so the bands are visual only and the scaling run-in itself takes `nameLevel + 1` (H2 by default; H3 or H4 when embedded).

## Core display terms

| Term | Meaning |
| --- | --- |
| **Property** | One label → value pair (`dt` / `dd`, optional `meta`) |
| **PropertyList** | Stacked or gridded properties (`dl`: `inline` / `divided` / `grid` / `cards`) — Core **molecule** |
| **ListItem** | One content-list row (`li`, optional checklist `status`) |
| **List** | Stacked content items (`ul` / `ol`, `unordered` / `ordered` / `checklist`) — Core **molecule** (not PropertyList) |
| **Stat** | Numeric display chip (`disk` / `arch` / `shield`) |
| **StatusDot** | Unlabeled readiness pip (same intents as Badge) |
| **Swatch** | Arbitrary data pigment sample (`--eevenkoto-swatch-color`, hairline border) |
| **Chip** | Interactive control chip (`selected`, optional `icon` / `swatchColor`) |
| **ChipGroup** | Accessible `<fieldset>` of toggleable Chips (`single` / `multiple` mode) |
| **Catalog** | Dense index grid of CatalogTiles |
| **Popover** | Raised floating panel chrome (CSS only; app owns open/position) |
| **TooltipCard** | Header / body / footer chrome nested in Popover (or standalone) — native `header` / `footer`, self-capping scroll body that is also Prose; not an in-page Card |
| **Card** | In-page sectioned surface (`article` + native `header` / flow / `footer`, `surface`, `accent`, `split`) |
| **Disclosure** | Native `<details>` / `<summary>` expander (`card` / `subtle` / `flush`) |
| **TableOfContents** | In-page jump-link `<nav>` (`rail` / `collapsible` / `auto`) |
| **SectionHeader** | Editorial header lockup (eyebrow, logo, heading, lead, actions, note) |
| **Workshop** | Core 2-column `split` workbench or `inline` generator chassis |
| **TierCard** | Membership / pricing tier comparison card |
| **AccountMenu** | Signed-out CTA or signed-in trigger + Popover account menu |
| **ProgressBar** | Indeterminate or determinate progress indicator (`inline` or `fixed`) |
| **FloatingBanner** | Fixed viewport-bottom consent / announcement bar |
| **Toast** | Transient feedback notification atom (`subtle` / `solid`, `inline` / `fixed-*`) |
| **Divider** | Horizontal rule atom (and bare `<hr>` inside Prose) |
| **InlineRef** | Core inline reference chrome (`name`, optional `href`); Popover trigger in Core demos |
| **Input** | Single-line **control chrome** only (fill / border / focus). Nest inside Field for forms. Uses `ariaLabel`, not `label`. |
| **Field** | Form **row**: visible `label` + control slot + hint/error. Default choice for data entry. |
| **emphasis** | Generic Stat / EquipmentBlock stat highlight (thicker stroke, etc.) |
| **saveProficient** | Domain flag on AbilityScore; maps to Stat `emphasis` + AT suffix |

## Domain inline terms

| Term | Meaning | Prop / type |
| --- | --- | --- |
| **AbilityName** | Responsive TTRPG ability name atom (collapses full name to 3-letter uppercase in narrow containers while keeping full AT text) | `AbilityNameProps` (`name`, `short?`, `variant?`) |
| **EntityRef** | Domain specialization of InlineRef with closed kinds | `EntityRefProps` (`name`, `kind`, `href?`, `unlinked?`, `locked?`) |
| **kind** | Closed EntityRef taxonomy (`condition`, `mechanic`, `ability`, `classFeature`, `feat`, `class`, `species`, `culture`, `background`, `spell`, `item`, `creature`) | `EntityRefKind` |
| **unlinked** | Known term with no page (InlineRef / EntityRef) | `unlinked` |
| **locked** | Gated destination; trailing lock Icon | `locked`, `lockedLabel` |

**Stat** (chip) and **Statblock** (entry) are different concepts that share a root word on purpose.

## Visible-string props

Use the prop that matches the role — do not force one name everywhere.

| Prop | Use for |
| --- | --- |
| `label` | Visible control/chrome copy and definition terms (Button, LinkButton, Badge, Property, AbilityScore header, **Field** visible label). **Not** used on Input. |
| `ariaLabel` | Input / Select / FloatingBanner: `aria-label` when there is no Field / visible label. |
| `text` | Typography primitives (Heading, Paragraph, Caption, ListItem, TableCell body, Toast) |
| `name` | Named entity or inline reference (Statblock creature, Spellblock spell, EquipmentBlock item, NpcCard, TierCard, StatblockFeature, InlineRef, EntityRef, AbilityName) |
| `title` | Section or surface heading (StatblockSection, Card, TooltipCard, SectionHeader, Workshop, ContentGate, MapFrame) |
| `value` | Numeric or definitional payload (Stat, Property, ProgressBar, Stepper) |
| `description` | Feature or option body after the primary label |
| `content` | HTML-only string body for composed hosts (Flow, Prose, Frame, Scroll, Popover); React/Vue/Astro use `children` / slots |

In markup, a Property `label` is the definition **term** (`dt`). The prop name stays **`label`**.

## Variant vocabulary

| Surface | Prop | Values mean |
| --- | --- | --- |
| Button | `variant` | Action hierarchy: `primary` / `secondary` / `ghost` |
| LinkButton | `variant` | CTA / standalone link hierarchy: `primary` / `secondary` / `ghost` (in-prose links stay InlineRef or bare `<a>`) |
| Badge / Notice | `variant` | Surface recipe: `subtle` / `solid` / `outline` |
| Toast | `variant` | Surface recipe: `subtle` / `solid` |
| Badge / Notice / Toast / StatusDot | `intent` | Feedback severity: `neutral` / `info` / `success` / `caution` / `critical` / `admin` |
| Chip | `selected` | Control selected / unselected |
| Heading / Paragraph / List | `tone` | Content weight: `primary` / `secondary` |
| Caption | `tone` | Content weight: `secondary` (default → `content-tertiary`) / `primary` / `accent` |
| List | `variant` | List kind: `unordered` / `ordered` / `checklist` |

`primary` is overloaded by design (control hierarchy vs content weight vs token slots). Prefer the table above over inventing parallel words.

Feedback uses **`caution`** / **`critical`** (not `warning` / `error`). Destructive actions use control **`destructive`** tokens / Menu `tone="destructive"` — that is separate from Badge intent.

## Button vs LinkButton vs InlineRef

Never put `href` on Button or wrap a Button in an `<a>`. Pick by **what happens**, not by how prominent it looks.

| Situation | Use |
| --- | --- |
| Hero / campaign “Start playing”, “Get the book”, “Read the rules” | **LinkButton** (`<a>`, required `href`) |
| Same-site page that is still a real URL | **LinkButton** |
| Form submit, dialog confirm, add/remove, open a modal or drawer | **Button** (`<button>`) |
| “Read more” or a term inside a paragraph | **InlineRef** / **EntityRef** (or a prose link) — not LinkButton |
| One main destination + quieter standalone destinations | LinkButton **primary** + **secondary** / **ghost** |
| Destination is not ready | Omit the CTA; do not ship a disabled LinkButton as the only signal |

LinkButton looks related to Button on purpose (marketing CTAs) but stays a link: end-scoop shape, hover translate, no visited purple. Button is for **doing**; LinkButton is for **going**.

## Form controls chooser

Pick the control based on **selection cardinality** (how many items can be chosen), **option count**, and **canvas space / scanning demand**.

| User Task / Scenario | Recommended | Why | When NOT to use |
| --- | --- | --- | --- |
| **Independent on/off toggle** (e.g. "I accept rules", "Equipped") | **Checkbox** | Standard binary switch. | Do not use Radio for standalone toggles. |
| **Multi-select from a list (0 to N)** (e.g. weapon traits, skills) | **CheckboxGroup** | Fieldset grouping checkboxes; supports budget `badge`. | If only ONE choice is allowed, use RadioGroup or Select. |
| **Compact filter chips / color swatches** (e.g. spell level filter, dye tray) | **ChipGroup** | Wrapping `<fieldset>` of `aria-pressed` Chips with `icon` / `swatchColor`. | For form submissions with native inputs/descriptions, use CheckboxGroup or RadioGroup. |
| **Single choice from 2–5 visible options** (e.g. Melee vs Ranged) | **RadioGroup** | All options visible for rapid comparison and arrow navigation. | If there are 6+ options or space is tight, use Select. |
| **Single choice from 6+ options** (e.g. 15 weapon classes, categories) | **Select** | Compact single-row height; mobile OS pickers; `<optgroup>`. | If options need instant visual comparison, use RadioGroup. |
| **In-page view switcher or mode toggle** (2–4 items) | **SegmentedControl** | Horizontal connected pill toolbar for view modes. | Not for form surveys or options with mechanics copy. |
| **Bounded small integer quantity or rank** (e.g. ranks 0–5, quantities 1–10) | **Stepper** | One-tap `+` / `−` adjustments with min/max bounds. | For large open-ended numbers (e.g. 500 gold), use Input. |
| **Free-form text, search, or large numbers** | **Field + Input** | Standard text-box surface with label and error copy. | Do not use for choosing from a closed predefined list. |

### Variant selection for Checkbox & Radio

- **`default` (inline)**: Compact, standard checkbox / radio circle with adjacent label. Best for simple one-line items in forms and settings.
- **`card`**: Rich card with title, optional description (mechanics copy), and optional badge (budget/tier). Best for item builders, spell selection, equipment loadouts.
- **`tile` (Radio only)**: Compact symmetric card with centered label and optional icon. Best in a 2–3 column grid (`layout="grid"`) for mutually exclusive modes, dice selection, or armor categories.

## Type layers

| Package | Canonical type name |
| --- | --- |
| `@eevenkoto/core` | `*Props` + `*ClassNames()` |
| `@eevenkoto/html` | `*Props` (HTML-only extensions stay as local `*Props` that extend core) |
| `@eevenkoto/react` | `*ComponentProps` (DOM attrs + core props) |
| `@eevenkoto/vue` | `*Props` on the component |
| `@eevenkoto/astro` | `*Props` in `.astro` frontmatter (`index.d.ts` re-exports) |

Do not introduce `*Args` aliases.

## File-name conventions

| Surface | Convention | Example |
| --- | --- | --- |
| Core TS sources | camelCase | `abilityScore.ts` |
| CSS / HTML folders & files | kebab-case | `ability-score/`, `primitive-tokens.css` |
| React / Vue / Astro / Storybook components | PascalCase | `AbilityScore.tsx`, `AbilityScore.astro` |
| BEM blocks | `eevenkoto-<block>` | `eevenkoto-ability-score` |
| camelCase props → BEM modifiers | kebab-case | `saveProficient` → `--save-proficient`, `runIn` → `--run-in` |

Public CSS import paths stay flat (`@eevenkoto/css/ability-score.css`) even when source lives under `core/` or `domain/`.

## Content license, readiness and gating (0.12)

| Term | Meaning | Prop / type |
| --- | --- | --- |
| **ContentLicense** | Which legal mode a text is read under | `'proprietary' \| 'open'` (never product names such as `teksti` / `srd`) |
| **LicenseBar** | Strip that shows the active license and legal links | `LicenseBarProps` (`activeLicense`, `placement`, `entries`) |
| **readiness** | Maturity of content (ready / preview / draft) | `readinessLabel` + `readinessIntent: BadgeIntent` |
| **ContentGate** | Page that explains why a document is locked | `ContentGateProps` (`currentTierLabel`, `requiredTierLabel`, `statusMessage`) |
| **tier** | A membership level | `*TierLabel`; `TierCard` for comparison |
| **checklist** | List variant with included / accent / excluded items | `List variant="checklist"`, `ListItemProps.status` |
| **details** | NPC / statblock footer PropertyList (never `traits`) | `NpcCardProps.details` |
| **svgHtml** | Trusted inline SVG for a map | `MapFrameProps.svgHtml` |

`*Html` props (`bodyHtml`, `descriptionHtml`, `captionHtml`, `nameHtml`, `valueHtml`) always accept pre-rendered inline/block HTML alongside plain strings and framework slots.
