# Glossary

Canonical vocabulary for Eevenkoto APIs, source layout, and docs. Prefer these names in props, types, file paths, and prose.

Also read: [Component taxonomy](?path=/docs/foundations-component-taxonomy--docs) · [Authoring composed components](?path=/docs/foundations-authoring-composed-components--docs) · [Minimum-class defaults](?path=/docs/foundations-minimum-class-defaults--docs) · [Packages](?path=/docs/foundations-packages--docs) (Button vs LinkButton chooser for agents)

## Locale policy

- **Public APIs are English** (prop names, type names, BEM blocks, defaults).
- **Product-language strings are data** — Finnish (or any locale) belongs in story / app props, not in `@eevenkoto/core`.
- English defaults (`Score`, `Modifier`, `Save`, `proficient`) may ship for AT labels; override them when the surrounding UI is localized (`scoreLabel`, `modifierLabel`, `saveLabel`, `proficientLabel`).

## Architecture terms

| Term | Meaning |
| --- | --- |
| **Core** | Product-agnostic chrome; no RPG vocabulary required |
| **Domain** | Eevenkoto content patterns (creatures, abilities, statblocks); may compose Core |
| **Atom** | One semantic unit + BEM classes |
| **Molecule** | Layout of atoms + local ARIA |
| **Organism** | Page-shaped composition, slots, outline |
| **Tier 1 / 2 / 3** | Token layers: primitives → semantics → component bridges |
| **Host default** | `.eevenkoto-<block>` alone = documented default look; see [Minimum-class defaults](?path=/docs/foundations-minimum-class-defaults--docs) |
| **Prose** | Scope for bare `h1`–`h6` / `p` / `ul` / `ol` / `li` type styles (compose with Flow for rhythm) |
| **Flow** | Vertical rhythm for stacked type (classed or Prose+Flow bare tags) |

## Domain entry stack

| Term | Meaning | Prop / type |
| --- | --- | --- |
| **Statblock** | Creature / entity **entry** organism | `StatblockProps` |
| **name** | Creature title | `name`, `nameLevel` |
| **flavor** | Optional lead paragraph | `flavor` |
| **typeLine** | Size / type caption | `typeLine` |
| **vitals** | Combat vitals PropertyList (AbilityScoreGroup **header**) | `vitals: PropertyItem[]` |
| **abilities** | Ability columns | `abilities: AbilityScoreProps[]` |
| **details** | Skills, gear, senses, languages, CR (AbilityScoreGroup **footer**) | `details: PropertyItem[]` |
| **section** | Named block (Actions, Reactions, …) | `StatblockSectionProps.title` |
| **feature** | Named action / trait / reaction line | `StatblockFeatureProps` (`name`, `description`) |
| **AbilityScore** | One ability column (label + score + modifier + save) | `AbilityScoreProps` |
| **AbilityScoreGroup** | Sandwich organism (header + grid + footer) | `AbilityScoreGroupProps` |

Do **not** use **traits** for the footer PropertyList — that word collides with feature-style “traits” in rules prose. The footer rail is **`details`**.

## Core display terms

| Term | Meaning |
| --- | --- |
| **Property** | One label → value pair (`dt` / `dd`) |
| **PropertyList** | Stacked properties (`dl`) — Core **molecule** |
| **ListItem** | One content-list row (`li`) |
| **List** | Stacked content items (`ul` / `ol`) — Core **molecule** (not PropertyList) |
| **Stat** | Numeric display chip (`disk` / `arch` / `shield`) |
| **Popover** | Raised floating panel chrome (CSS only; app owns open/position) |
| **TooltipCard** | Header / body / footer chrome nested in Popover (or standalone) — not an in-page Card |
| **Card** | In-page sectioned surface (`__header` / `__body` / `__footer`) |
| **InlineRef** | Core inline reference chrome (`name`, optional `href`); Popover trigger in Core demos |
| **Input** | Single-line **control chrome** only (fill / border / focus). Nest inside Field for forms. Uses `ariaLabel`, not `label`. |
| **Field** | Form **row**: visible `label` + control slot + hint/error. Default choice for data entry. |
| **emphasis** | Generic Stat highlight (thicker stroke, etc.) |
| **saveProficient** | Domain flag on AbilityScore; maps to Stat `emphasis` + AT suffix |

## Domain inline terms

| Term | Meaning | Prop / type |
| --- | --- | --- |
| **EntityRef** | Domain specialization of InlineRef with closed kinds | `EntityRefProps` (`name`, `kind`, `href?`) |
| **kind** | Closed EntityRef taxonomy (`condition`, `mechanic`, …) | `EntityRefKind` |

**Stat** (chip) and **Statblock** (entry) are different concepts that share a root word on purpose.

## Visible-string props

Use the prop that matches the role — do not force one name everywhere.

| Prop | Use for |
| --- | --- |
| `label` | Visible control/chrome copy and definition terms (Button, LinkButton, Badge, Property, AbilityScore header, **Field** visible label). **Not** used on Input. |
| `ariaLabel` | Input-only: `aria-label` when there is no Field / visible label (chrome search). |
| `text` | Typography primitives (Heading, Paragraph, Caption, ListItem, TableCell body) |
| `name` | Named entity or inline reference (Statblock creature, StatblockFeature, InlineRef, EntityRef) |
| `title` | Section heading (StatblockSection, TooltipCard header) |
| `value` | Numeric or definitional payload (Stat, Property) |
| `description` | Feature body after the run-in name |
| `content` | HTML-only string body for composed hosts (Flow, Popover panel); React/Vue use `children` / slots |

In markup, a Property `label` is the definition **term** (`dt`). The prop name stays **`label`**.

## Variant vocabulary

| Surface | Prop | Values mean |
| --- | --- | --- |
| Button | `variant` | Action hierarchy: `primary` / `secondary` / `ghost` |
| LinkButton | `variant` | CTA hierarchy: `primary` / `secondary` (no ghost — in-prose links stay InlineRef) |
| Badge | `variant` | Surface recipe: `subtle` / `solid` / `outline` |
| Badge | `intent` | Feedback severity: `neutral` / `info` / `success` / `caution` / `critical` / `admin` |
| Heading / Paragraph / Caption / List | `tone` | Content weight: `primary` / `secondary` |
| List | `variant` | List kind: `unordered` / `ordered` |

`primary` is overloaded by design (control hierarchy vs content weight vs token slots). Prefer the table above over inventing parallel words.

Feedback uses **`caution`** / **`critical`** (not `warning` / `error`). Destructive actions use control **`destructive`** tokens / Button examples — that is separate from Badge intent.

## Button vs LinkButton vs InlineRef

Never put `href` on Button or wrap a Button in an `<a>`. Pick by **what happens**, not by how prominent it looks.

| Situation | Use |
| --- | --- |
| Hero / campaign “Start playing”, “Get the book”, “Read the rules” | **LinkButton** (`<a>`, required `href`) |
| Same-site page that is still a real URL | **LinkButton** |
| Form submit, dialog confirm, add/remove, open a modal or drawer | **Button** (`<button>`) |
| “Read more” or a term inside a paragraph | **InlineRef** (or a prose link) — not LinkButton |
| One main destination + one quieter destination | LinkButton **primary** + **secondary** (no ghost) |
| Destination is not ready | Omit the CTA; do not ship a disabled LinkButton as the only signal |

LinkButton looks related to Button on purpose (marketing CTAs) but stays a link: end-scoop shape, hover translate, no visited purple. Button is for **doing**; LinkButton is for **going**.

## Type layers

| Package | Canonical type name |
| --- | --- |
| `@eevenkoto/core` | `*Props` + `*ClassNames()` |
| `@eevenkoto/html` | `*Props` (HTML-only extensions stay as local `*Props` that extend core) |
| `@eevenkoto/react` | `*ComponentProps` (DOM attrs + core props) |
| `@eevenkoto/vue` | `*Props` on the component |

Do not introduce `*Args` aliases.

## File-name conventions

| Surface | Convention | Example |
| --- | --- | --- |
| Core TS sources | camelCase | `abilityScore.ts` |
| CSS / HTML folders & files | kebab-case | `ability-score/`, `primitive-tokens.css` |
| React / Vue / Storybook components | PascalCase | `AbilityScore.tsx` |
| BEM blocks | `eevenkoto-<block>` | `eevenkoto-ability-score` |
| camelCase props → BEM modifiers | kebab-case | `saveProficient` → `--save-proficient`, `runIn` → `--run-in` |

Public CSS import paths stay flat (`@eevenkoto/css/ability-score.css`) even when source lives under `core/` or `domain/`.
