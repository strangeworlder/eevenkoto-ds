# Packages

Eevenkoto ships as separate npm packages so CSS stays framework-free and each runtime gets a thin binding.

| Package | Role |
| --- | --- |
| `@eevenkoto/css` | Tokens, base styles, and Core/Domain component CSS |
| `@eevenkoto/core` | Shared prop types + `*ClassNames()` helpers (no DOM) |
| `@eevenkoto/html` | Canonical vanilla API — HTML templates + `render*` |
| `@eevenkoto/react` | Thin React wrappers over the same classes |
| `@eevenkoto/vue` | Thin Vue wrappers over the same classes |
| `@eevenkoto/astro` | Thin Astro `.astro` wrappers with native slots over the same classes |

Source folders inside each package follow **Core vs Domain** and **Atoms / Molecules / Organisms** (see [Component taxonomy](?path=/docs/foundations-component-taxonomy--docs) and [Glossary](?path=/docs/foundations-glossary--docs)). Root barrels keep a stable public API.

## Source of truth

1. **CSS** defines appearance (`@eevenkoto/css`).
2. **Core package** defines the public prop contract and BEM class assembly (`@eevenkoto/core`).
3. **HTML** is the reference markup implementation used by this Storybook.
4. **React / Vue / Astro** only map props → the same class strings and elements (Flow uses children / default slot instead of a `content` string).

`@eevenkoto/css` is an **optional peer** of html/react/vue/astro: bindings assemble classes without injecting styles. Import CSS in the host app or the UI is unstyled.

Import styles explicitly in the host app:

```ts
import '@eevenkoto/css/styles.css';
import '@eevenkoto/css/button.css';
```

Component docs briefly show HTML, React, and Vue usage under **Framework packages**. The live Canvas and Controls remain HTML-driven.

## Button vs LinkButton (marketing / agents)

| Situation | Use | Host |
| --- | --- | --- |
| Prominent “go to this URL” CTA (hero, campaign, empty state) | **LinkButton** | `<a class="eevenkoto-link-button" href="…">` |
| In-page action (submit, dialog, add/remove, open UI) | **Button** | `<button type="button" class="eevenkoto-button">` |
| Term or “read more” in running text | **InlineRef** (optional `href`) | not a CTA |

Do **not** put `href` on Button or wrap Button in an anchor. Same-site pages with a real URL still use LinkButton. Import `@eevenkoto/css/link-button.css` separately from `button.css`. Full chooser: [Glossary — Button vs LinkButton vs InlineRef](?path=/docs/foundations-glossary--docs#button-vs-linkbutton-vs-inlineref).

## Theming & upgrading in consuming apps

- **Theme switching:** Set `data-theme="light"` or `data-theme="dark"` on `<html>` (or scope a dark region with `data-surface-mode="dark"`). `@eevenkoto/css/styles.css` includes `tokens.css`, which flips all Tier 2 semantic color tokens automatically (`color-scheme: light` / `dark`) — no host-app dark-mode CSS patches are needed.
- **Tokens & overrides:** Consume Tier 2 tokens (`--eevenkoto-color-*`, `--eevenkoto-font-size-*`, `--eevenkoto-font-weight-*`, `--eevenkoto-space-*`, `--eevenkoto-radius-*`, `--eevenkoto-duration-*`, `--eevenkoto-ease-*`) — never import `primitive-tokens.css` or set private `--_eevenkoto-*` component bridges. Customize components via public `--eevenkoto-<component>-*` variables (see [Tier 3 — Component scoping](?path=/docs/foundations-color-tokens-tier-3-component-scoping--docs)).
- **Upgrading an existing site:** Follow the repo’s `docs/migration-token-architecture-and-a11y.md` and `CHANGELOG.md` (also bundled into `/llms-full.txt` under **Upgrading & Consumer Migration Guide** for coding agents).
