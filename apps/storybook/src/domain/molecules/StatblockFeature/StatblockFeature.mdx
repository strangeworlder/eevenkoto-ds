# StatblockFeature

**StatblockFeature** is the small molecule for a named **action, trait, or reaction**: an **H3 run-in** heading flowing into a Paragraph. Semantic outline stays under a section H2; visual weight matches micro H6 (sans, bold italic).

<Canvas of={StatblockFeatureStories.Default} />

```html
<div class="eevenkoto-statblock-feature">
  <h3 class="eevenkoto-heading eevenkoto-heading--3 eevenkoto-heading--primary eevenkoto-heading--run-in">Kalpa</h3>
  <p class="eevenkoto-paragraph eevenkoto-paragraph--md eevenkoto-paragraph--primary">
    <em>Lähitaisteluhyökkäys:</em> +3, ulottuvuus 2 m. <em>Osuma:</em> 5 (1n8 + 1) iskuvahinkoa.
  </p>
</div>
```

## Why to use

Feature names should participate in the document outline without orphaning a full-width heading above a one-line mechanic. Run-in H3 keeps the name on the same line as the body while remaining a real heading.

## When to use

## Anatomy

1. **Root** — `div.eevenkoto-statblock-feature`
2. **Name** — `h3.eevenkoto-heading--3.eevenkoto-heading--run-in` (visual remap → micro)
3. **Body** — sibling `p.eevenkoto-paragraph` (`display: inline` after run-in)

## Visual remap

Inside `.eevenkoto-statblock-feature`, the H3 run-in overrides Heading bridges to match default H6:

| Axis | Value |
| --- | --- |
| Family | `--eevenkoto-font-sans` |
| Size | `--eevenkoto-font-size-heading-6` (= body-md) |
| Weight / style | Bold italic |
| Color | `--eevenkoto-color-control-secondary-icon` |
| Display | `inline-block` + period suffix + `--eevenkoto-heading-run-in-gap` |

Run-in structure (inline + suffix + sibling paragraph) is defined on Heading for levels **3** and **6**. See [Heading — runIn](?path=/docs/core-atoms-heading--docs#runin-h3--h6).

## Content guidelines

- Keep `name` short (one or two words / a proper noun).
- Put attack formulas, ranges, and triggers in `description`.
- For HTML renderer: trusted inline markup (`<em>`, etc.) is fine in `description`.
- For React: pass `description` as `ReactNode` when you need rich text without HTML strings.

## Accessibility

- The feature name remains an `<h3>` — do not demote it to a span.
- Place features only under an H2 (StatblockSection) so the outline does not jump H1 → H3.
- Trailing gap after the name uses `--eevenkoto-heading-run-in-gap` (default `0.35em`) so the body does not collide with the suffix.

## API reference

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `name` | `string` | — | Feature title (H3 run-in). |
| `description` | `string` (HTML) / `ReactNode` (React) | — | Body after the run-in. |
