# Tokens

Design tokens are the shared CSS custom properties for color intent, typography, spacing, radius, and line width. **When building UI, consume semantic (Tier 2) tokens and metrics — never hue primitives.**

```css
/* Correct: semantic intent */
.eevenkoto-card {
  background-color: var(--eevenkoto-color-surface-raised);
  color: var(--eevenkoto-color-content-primary);
  border-color: var(--eevenkoto-color-boundary-subtle);
}
```

## Why to use

Tokens keep product UI consistent, themeable, and accessible without hard-coding pigments. Semantic names describe *role* (`control-primary-background`, `content-primary`) so engineers choose intent instead of guessing between `turquoise-state` and `turquoise-primary`.

## When to use

Reach for tokens whenever you style a layout, utility, or component. Prefer an existing semantic token; only escalate to new primitives when intent is missing from Tier 2 and a designer confirms the pigment.

## Semantic colors

These are the **consumable** color tokens (Tier 2) currently defined in `tokens.css`. Use them in layouts, utilities, and as Tier 3 bridge fallbacks.

| Domain | Examples | Use for |
| --- | --- | --- |
| `control` | `--eevenkoto-color-control-primary-background` | Buttons, chips, and other contained actions |
| `surface` | `--eevenkoto-color-surface-canvas` | Page canvases, cards, sunken wells |
| `content` | `--eevenkoto-color-content-primary` | Body text and secondary/disabled copy |
| `boundary` | `--eevenkoto-color-boundary-focus-outer` | Dividers and dual-halo focus rings |
| `depth` | `--eevenkoto-color-depth-shadow-umbra` | Elevation shadows |

## Primitives (internal)

Hue pigments in `primitivetokens.css`. Tier 2 maps these to semantic roles. **Components and product CSS must never import them.**
