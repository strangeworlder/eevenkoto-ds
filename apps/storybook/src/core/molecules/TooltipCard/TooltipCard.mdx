# Tooltip Card

Header / body / footer Calling Card preview surface: `surface-raised` with a `0px` outer trim, `4px` paper margin, concave-scooped inner passe-partout, and crisp cardstock shadow. Standalone it reads as a compact elevated Calling Card; nested in [Popover](?path=/docs/core-atoms-popover--docs) it snaps Popover to `0px` Calling Card trim and sheds its duplicate outer stroke while retaining the inner passe-partout.

<Canvas of={TooltipCardStories.Default} />

```html
<div class="eevenkoto-tooltip-card">
  <header>
    <h2>Cure Wounds</h2>
  </header>
  <div class="eevenkoto-tooltip-card__body eevenkoto-prose">
    <p>A creature you touch regains hit points.</p>
    <ul>
      <li>This spell has no effect on undead or constructs.</li>
    </ul>
  </div>
  <footer><a href="/spells/cure-wounds">Avaa sivu →</a></footer>
</div>
```

The host styles native `<header>` and `<footer>`, and the title is a real heading (default **H2**) remapped on the panel — do not compose the Heading atom. The body keeps a class because it is the scroll region: it caps itself and scrolls, so long copy never pushes the footer out of the panel. It also carries `eevenkoto-prose`, because bare `p` / `ul` / `ol` / `li` only get type styles under [Prose](?path=/docs/core-molecules-prose--docs). `tooltip-card.css` imports that sheet, so a preview does not depend on a page-level Prose wrapper. `__header` / `__footer` remain optional aliases.

## TooltipCard vs Card / InlineRef / EntityRef

| Need | Use |
| --- | --- |
| In-page sectioned content tile (header / body / footer) | **[Card](?path=/docs/core-molecules-card--docs)** |
| Floating preview panel chrome (often inside Popover) | **TooltipCard** |
| Inline term trigger in body copy (Core) | **[InlineRef](?path=/docs/core-atoms-inlineref--docs)** |
| Inline term with closed rules kinds (Domain) | **[EntityRef](?path=/docs/domain-atoms-entityref--docs)** |
| Positioning / arrow shell | [Popover](?path=/docs/core-atoms-popover--docs) |

Agents: Core docs compose **InlineRef → Popover → TooltipCard**. Do not import Domain EntityRef from Core stories. EntityRef may replace InlineRef in product when kinds matter.

## Why to use

Preview panels need a compact elevated surface with an optional title, scrollable body, and footer link — without inventing a one-off panel or overloading page [Card](?path=/docs/core-molecules-card--docs). TooltipCard is that chrome; Popover owns placement.

## Long body

<Canvas of={TooltipCardStories.ScrollingBody} />

`__body` owns its own cap (`--eevenkoto-tooltip-card-body-max-block-size`) and scrolls past it, so the header and footer stay pinned. There is no opt-in prop and no [Scroll](?path=/docs/core-atoms-scroll--docs) import: a floating preview that grows without bound is never the behavior you want.

## Flush body & pre-rendered HTML

Set `flush` (`.eevenkoto-tooltip-card--flush`) to zero body padding (`--eevenkoto-tooltip-card-body-pad: 0`) when embedding a full-bleed rules block inside the preview while keeping header and footer padded. Pass `bodyHtml` when rendering trusted pre-rendered HTML directly inside `__body` (framework children/default slot takes precedence over `bodyHtml`, which takes precedence over `body`).

## Inside a Popover

<Canvas of={TooltipCardStories.InsidePopover} />

As a direct Popover child it snaps Popover to `0px` Calling Card trim, sheds its duplicate outer border and shadow, zeroes the panel padding, and keeps the inner passe-partout so the two surfaces never double up.

## Anatomy

| Part | Role |
| --- | --- |
| Host | `<div class="eevenkoto-tooltip-card">` (`--flush` zeroes body padding) |
| Header | descendant `header` (optional `.eevenkoto-tooltip-card__header`) |
| Title | `h2` (or `h3` via `titleLevel`) inside `header` |
| Body | `.eevenkoto-tooltip-card__body.eevenkoto-prose` — capped scroll region; Prose so bare `p` / lists style |
| Footer | descendant `footer` (optional `.eevenkoto-tooltip-card__footer`) |

## Usage

```ts
import '@eevenkoto/css/tooltip-card.css';
import { renderTooltipCard } from '@eevenkoto/html';
```

## API reference

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `title` | `string` | — | Visible heading inside `<header>`. |
| `titleLevel` | `2 \| 3` | `2` | Heading level (`h2` or `h3`) for `title`. |
| `header` | `string` / slot | — | Custom `<header>` content (`header` prop in HTML/React; `#header` / `slot="header"` in Vue/Astro). |
| `body` | `string` | — | Plain-text body copy rendered in `__body` (compact `body-sm` interior rhythm). |
| `bodyHtml` | `string` | — | Trusted pre-rendered HTML for `__body` (takes precedence over `body`). |
| `content` | `string` / slot | — | Scrollable body content (`content` in `@eevenkoto/html`; `children` / default slot in React, Vue, and Astro). |
| `footer` | `string` / slot | — | Pinned footer content inside `<footer>`. |
| `flush` | `boolean` | `false` | Zeroes `__body` padding for full-bleed embedded blocks (`eevenkoto-tooltip-card--flush`). |
| `id` | `string` | — | Host element `id` (React, Vue, and Astro HTML attributes). |

## Framework packages

`tooltip-card.css` imports `prose.css` automatically. Nest directly inside `Popover` to shed duplicate outer border/shadow.

```ts
import '@eevenkoto/css/styles.css';
import '@eevenkoto/css/tooltip-card.css';
import { renderTooltipCard } from '@eevenkoto/html';

renderTooltipCard({
  title: 'Paralyzed',
  body: 'A paralyzed creature is incapacitated and cannot move or speak.',
});
```

```tsx
import '@eevenkoto/css/styles.css';
import '@eevenkoto/css/tooltip-card.css';
import { TooltipCard } from '@eevenkoto/react';

<TooltipCard title="Paralyzed">
  <p>A paralyzed creature is incapacitated and cannot move or speak.</p>
</TooltipCard>
```

