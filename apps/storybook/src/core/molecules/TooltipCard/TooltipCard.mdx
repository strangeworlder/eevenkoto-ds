# Tooltip Card

Header / body / footer on a popover-like surface: `surface-raised` plus the two depth shadows. Standalone it reads as a compact elevated card; nested in [Popover](?path=/docs/core-atoms-popover--docs) it sheds its own chrome.

<Canvas of={TooltipCardStories.Default} />

```html
<div class="eevenkoto-tooltip-card">
  <header>
    <h2>Cure Wounds</h2>
  </header>
  <div class="eevenkoto-tooltip-card__body">
    <p>A creature you touch regains hit points.</p>
  </div>
  <footer><a href="/spells/cure-wounds">Avaa sivu →</a></footer>
</div>
```

The host styles native `<header>` and `<footer>`, and the title is a real heading (default **H2**) remapped on the panel — do not compose the Heading atom. The body keeps a class because it is the scroll region: it caps itself and scrolls, so long copy never pushes the footer out of the panel. `__header` / `__footer` remain optional aliases.

## TooltipCard vs Card / InlineRef / EntityRef

| Need | Use |
| --- | --- |
| In-page sectioned content tile (header / body / footer) | **[Card](?path=/docs/core-molecules-card--docs)** |
| Floating preview panel chrome (often inside Popover) | **TooltipCard** |
| Inline term trigger in body copy (Core) | **[InlineRef](?path=/docs/core-atoms-inlineref--docs)** |
| Inline term with closed rules kinds (Domain) | **[EntityRef](?path=/docs/domain-atoms-entityref--docs)** |
| Positioning / arrow shell | [Popover](?path=/docs/core-atoms-popover--docs) |

Agents: Core docs compose **InlineRef → Popover → TooltipCard**. Do not import Domain EntityRef from Core stories. EntityRef may replace InlineRef in product when kinds matter.

## Why to use

Preview panels need a compact elevated surface with an optional title, scrollable body, and footer link — without inventing a one-off panel or overloading page [Card](?path=/docs/core-molecules-card--docs). TooltipCard is that chrome; Popover owns placement.

## Long body

<Canvas of={TooltipCardStories.ScrollingBody} />

`__body` owns its own cap (`--eevenkoto-tooltip-card-body-max-block-size`) and scrolls past it, so the header and footer stay pinned. There is no opt-in prop and no [Scroll](?path=/docs/core-atoms-scroll--docs) import: a floating preview that grows without bound is never the behavior you want.

## Inside a Popover

<Canvas of={TooltipCardStories.InsidePopover} />

As a direct Popover child it drops its own border, radius, and shadow and zeroes the panel padding, so the two surfaces never double up.

## Anatomy

| Part | Role |
| --- | --- |
| Host | `<div class="eevenkoto-tooltip-card">` |
| Header | descendant `header` (optional `.eevenkoto-tooltip-card__header`) |
| Title | `h2` (or `h3` via `titleLevel`) inside `header` |
| Body | `.eevenkoto-tooltip-card__body` — classed because it is the capped scroll region |
| Footer | descendant `footer` (optional `.eevenkoto-tooltip-card__footer`) |

## Usage

```ts
import '@eevenkoto/css/tooltip-card.css';
import { renderTooltipCard } from '@eevenkoto/html';
```
