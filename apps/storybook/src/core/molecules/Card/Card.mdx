# Card

Self-contained **content** surface. The host is an `<article>` wrapping optional `<header>`, flow (`<p>`, …), and `<footer>`. The host class alone styles those tags — no region BEM is required for the default look. Host alone is a flat raised surface with hairline dividers and no interaction affordance.

<Canvas of={CardStories.Default} />

```html
<article class="eevenkoto-card">
  <header>
    <h2>Cloak of Elvenkind</h2>
  </header>
  <p>
    While you wear this cloak with its hood up, Wisdom (Perception) checks made to see you have
    disadvantage.
  </p>
  <footer>Wondrous item, uncommon</footer>
</article>
```

The title is a real heading (default **H2**). Card remaps the look on the header — do not compose the Heading atom. `__header` / `__body` / `__footer` remain optional aliases.

## Card vs Frame / Notice

| Need | Use |
| --- | --- |
| Thin portable bordered box (charts, tables, token panels) | **[Frame](?path=/docs/core-atoms-frame--docs)** |
| Sectioned content with header / body / footer rhythm | **Card** |
| Elevation or clickable summary tile | Card `--elevated` / `--interactive` |
| Dense entity index (name + pip) | **[Catalog](?path=/docs/core-molecules-catalog--docs)** |
| Status / gate / warning banner (intent-colored) | **[Notice](?path=/docs/core-molecules-notice--docs)** — not Card |

## Why to use

Item entries, paywall summaries, and other self-contained chunks need a surface with optional title and footer chrome — not a full page layout and not a bare Frame. Card owns that sectioned box so products do not invent one-off bordered panels for every teaser. Copy-paste HTML is a document (`article` + heading), not a div sandwich.

## Interactive

The host stays `<article>`. `renderCard({ href })` wraps the sections in an inner link and adds `--interactive`.

```html
<article class="eevenkoto-card eevenkoto-card--interactive">
  <a href="#item">
    <header>
      <h2>Open the item entry</h2>
    </header>
    <p>Interactive cards gain hover, focus, and disabled affordances.</p>
  </a>
</article>
```

## Anatomy

| Part | Role |
| --- | --- |
| Host | `<article class="eevenkoto-card">` |
| Header | descendant `header` (optional `.eevenkoto-card__header`) |
| Title | `h2` (or `h3` via `titleLevel`) inside `header` |
| Body | flow siblings (`p`, …) — optional `.eevenkoto-card__body` grouping alias |
| Footer | descendant `footer` (optional `.eevenkoto-card__footer`) |
| Interactive | inner `a[href]` wrapping the sections; `--interactive` on the article |

## Framework packages

Hand-authored HTML is the reference. `renderCard` emits the same tags from `title` / `body` / `footer`.

```ts
import '@eevenkoto/css/card.css';
import { renderCard } from '@eevenkoto/html';

renderCard({
  title: 'Cloak of Elvenkind',
  body: 'While you wear this cloak with its hood up, Wisdom (Perception) checks made to see you have disadvantage.',
  footer: 'Wondrous item, uncommon',
});
```

```tsx
import { Card } from '@eevenkoto/react';

<Card title="Cloak of Elvenkind" footer="Wondrous item, uncommon">
  While you wear this cloak with its hood up, Wisdom (Perception) checks made to see you have
  disadvantage.
</Card>
```

Pair `--interactive` with a real inner link so keyboard activation works; `aria-disabled="true"` on the article or the inner `a` carries the disabled recipe.
