# PropertyList

**PropertyList** is the Core **molecule** that stacks **Property** rows in a semantic definition list (`dl`). Property itself is the row atom (`dt` / `dd` inside a grouping `div`).

HTML5 allows a grouping `div` inside `dl` so each pair can be one flex row (`.eevenkoto-property`) without adjacent-sibling hacks. The colon after the term is rendered by CSS (`dt::after`), not stored in the label string.

<Canvas of={PropertyListStories.Default} />

```html
<dl class="eevenkoto-property-list">
  <div class="eevenkoto-property">
    <dt class="eevenkoto-property__label">Defense</dt>
    <dd class="eevenkoto-property__value">15</dd>
  </div>
  <div class="eevenkoto-property">
    <dt class="eevenkoto-property__label">Initiative</dt>
    <dd class="eevenkoto-property__value">+1 (11)</dd>
  </div>
</dl>
```

## Why to use

Combat vitals, skills, senses, languages, and challenge lines are definitional metadata. A real `dl` exposes that relationship to assistive tech and keeps Statblock rails honest — no bold Paragraph + `<br>` scaffolding.

## Anatomy

1. **PropertyList** — `dl.eevenkoto-property-list` (column flex, `width: 100%`)
2. **Property** — grouping `div.eevenkoto-property` (`width: 100%`, flex row)
3. **Label** — `dt.eevenkoto-property__label` (+ `::after` colon)
4. **Value** — `dd.eevenkoto-property__value` (`flex: 1` so long values use remaining space)

### Why the grouping `div`?

`<dl>` children are `dt` / `dd` (and, in HTML5, a grouping `div`). The wrapper is the BEM block for one row so label and value can sit on a single flex line. Without it, pairing would rely on brittle adjacent selectors.

## Layout & density

| Token / rule | Default | Role |
| --- | --- | --- |
| `--eevenkoto-property-list-gap` | `--eevenkoto-space-2` | Space between rows |
| `--eevenkoto-property-gap` | `0.35em` | Space between label and value |
| Row width | `100%` | Fills the rail / container, including narrow AbilityScoreGroup breakpoints |

## Accessibility

- Prefer PropertyList as the public entry; Property alone is a fragment for composition.
- Labels should be human language terms; values can include formula text (`9 (2n8)`).
- Do not use PropertyList for narrative paragraphs — use Paragraph.

## API reference

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `items` (list) | `PropertyItem[]` | — | Rows to render. |
| `label` (item) | `string` | — | Term (no colon). |
| `value` (item) | `string` | — | Detail text. |

```ts
export interface PropertyItem {
  label: string;
  value: string;
}

export interface PropertyListProps {
  items: PropertyItem[];
}
```

### CSS classes

| Class | Role |
| --- | --- |
| `eevenkoto-property-list` | `dl` root |
| `eevenkoto-property` | Row group |
| `eevenkoto-property__label` | `dt` |
| `eevenkoto-property__value` | `dd` |

### Public CSS override tokens

| Token | Purpose |
| --- | --- |
| `--eevenkoto-property-list-gap` | Gap between rows |
| `--eevenkoto-property-list-margin-block` | List block margins |
| `--eevenkoto-property-label-color` / `-value-color` | Ink |
| `--eevenkoto-property-font-size` | Type size (defaults to `body-md`) |
| `--eevenkoto-property-gap` | Label↔value gap |
| `--eevenkoto-property-label-weight` | Term weight (defaults to bold) |

Required CSS: `property.css`.
