# Menu

Vertical **navigation** list. The host is a `<nav>` wrapping nested `<ul>` / `<li>` / `<a>`. Branches are native `<details>` / `<summary>`. The host class alone styles those tags — no item BEM is required for the default look. Current page uses `aria-current="page"`.

<Canvas of={MenuStories.Default} />

```html
<nav class="eevenkoto-menu" aria-label="Account">
  <ul>
    <li><a href="/profile">Profile</a></li>
    <li><a href="/library" aria-current="page">My library</a></li>
    <li><hr></li>
    <li><a href="/sign-out">Sign out</a></li>
  </ul>
</nav>
```

Hover and selection come from Tier 2 **`control`**; ink, group labels, and the disabled state come from **`content`**. Disclosure chevrons are CSS on `summary` (no Icon). Import `icon.css` only when lock icons may render.

## Why to use

Account menus, view switchers, and worldbook sidebars all need a compact vertical list of destinations. Menu owns that chrome — flat rows for Popover menus, nested `group` branches for eevenko.to-style trees — without baking open/position or routing into the DS. Copy-paste HTML navigates with no app JS.

## Nested nav

Branches nest arbitrarily. Root summaries use uppercase chrome; deeper summaries stay sentence case. Children indent with `--eevenkoto-menu-indent`.

```html
<nav class="eevenkoto-menu eevenkoto-menu--embedded" aria-label="Worldbook">
  <ul>
    <li>
      <details open>
        <summary>Lajit</summary>
        <ul>
          <li><a href="#human" aria-current="page">Ihminen</a></li>
        </ul>
      </details>
    </li>
  </ul>
</nav>
```

## Locked items

`locked` adds a trailing lock Icon named by `lockedLabel` (default “Locked”). Keep `href` when signing in still navigates somewhere — the row stays a link with `aria-disabled`; drop it and the row renders as a disabled button. The lock draws in `currentColor`, so it follows item ink through selection and the disabled state instead of pulling a separate accent.

## Anatomy

| Part | Role |
| --- | --- |
| Host | `<nav class="eevenkoto-menu">` |
| List | descendant `ul` / `li` (no extra class) |
| Row | `a`, `button`, or `summary` (optional `.eevenkoto-menu__item`) |
| Current page | `aria-current="page"` on the link |
| `__header` | Static group label (`p` inside `li`) |
| `hr` | Rule between clusters |
| `details` | Nested branch |
| `summary` | Disclosure control (CSS chevron) |
| Nested `ul` | Indented children |

## API reference

| Entry `kind` | Fields |
| --- | --- |
| `item` (default) | `id`, `label`, `href?`, `selected?`, `disabled?`, `locked?`, `lockedLabel?`, `status?`, `statusLabel?` |
| `header` | `label` |
| `separator` | — |
| `group` | `id`, `label`, `expanded?`, `children: MenuEntry[]` |

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `entries` | `MenuEntry[]` | — | List data. |
| `label` | `string` | — | Accessible name (`aria-label` on `nav`). |
| `embedded` | `boolean` | `false` | Transparent flush surface. |

## Framework packages

Hand-authored HTML is the reference. `renderMenu` emits the same tags from `entries`.

```ts
import '@eevenkoto/css/menu.css';
import { renderMenu } from '@eevenkoto/html';

renderMenu({
  label: 'Worldbook',
  entries: [
    {
      kind: 'group',
      id: 'species',
      label: 'Lajit',
      expanded: true,
      children: [
        { id: 'human', label: 'Ihminen', href: '/lajit/ihminen' },
        { id: 'troll', label: 'Peikko', href: '/lajit/peikko' },
      ],
    },
  ],
});
```

```tsx
import { Menu } from '@eevenkoto/react';

<Menu label="Worldbook" entries={entries} />
```

The host is `<nav>`, not `role="menu"`. Add menu semantics and arrow-key handling in the app only when you also implement the keyboard contract. Nested expand/collapse uses native `<details>`.
