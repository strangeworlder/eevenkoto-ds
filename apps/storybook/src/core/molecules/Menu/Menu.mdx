# Menu

Vertical **action or navigation** list. Entries are data: an `item`, a static `header`, a `separator`, or a nested **`group`** (disclosure branch). Items render as `<button>` by default and as `<a>` when `href` is set. Groups render as `<details>` / `<summary>` so multi-level expand works without app JS.

<Canvas of={MenuStories.Default} />

Hover and selection come from Tier 2 **`control`**; ink, group labels, and the disabled state come from **`content`**. Import `icon.css` whenever groups (chevrons) may render.

## Why to use

Account menus, view switchers, and worldbook sidebars all need a compact vertical list of actions or destinations. Menu owns that chrome — flat rows for Popover menus, nested `group` branches for eevenko.to-style trees — without baking open/position or routing into the DS.

## Nested nav

Branches nest arbitrarily. Root summaries use uppercase chrome; deeper summaries stay sentence case. Children indent with `--eevenkoto-menu-indent`.

## Anatomy

| Part | Role |
| --- | --- |
| Host | `.eevenkoto-menu` |
| `__item` | Button or link row |
| `__header` | Static group label (not expandable) |
| `__separator` | Rule between clusters |
| `__branch` | `<details>` nest |
| `__summary` | Disclosure control (`__item` + chevron) |
| `__group` | Indented children stack |

## API reference

| Entry `kind` | Fields |
| --- | --- |
| `item` (default) | `id`, `label`, `href?`, `selected?`, `disabled?` |
| `header` | `label` |
| `separator` | — |
| `group` | `id`, `label`, `expanded?`, `children: MenuEntry[]` |

## Framework packages

```ts
import '@eevenkoto/css/menu.css';
import '@eevenkoto/css/icon.css';
import { renderMenu } from '@eevenkoto/html';

renderMenu({
  label: 'Worldbook',
  entries: [
    {
      kind: 'group',
      id: 'species',
      label: 'Lajit',
      expanded: true,
      children: [
        { id: 'human', label: 'Ihminen', href: '/lajit/ihminen' },
        { id: 'troll', label: 'Peikko', href: '/lajit/peikko' },
      ],
    },
  ],
});
```

```tsx
import { Menu } from '@eevenkoto/react';

<Menu label="Worldbook" entries={entries} />
```

The host ships `role="group"`, not `role="menu"` — add menu semantics and arrow-key handling in the app only when you also implement the keyboard contract. Nested expand/collapse uses native `<details>`.
