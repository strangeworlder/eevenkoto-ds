# Icon

Inline SVG **chrome** on a 16×16 viewBox: size ladder + `currentColor` fill. Icon does **not** own the glyph list.

Names and path data are **tokens** in `@eevenkoto/core` (`tokens/icons`: `ICON_NAMES`, `iconPaths`, `BUTTON_ICON_NAMES`). See the full catalog under [Foundations → Tokens → Icons](?path=/docs/foundations-tokens--docs#icons).

Button composes this atom and restricts `icon` to `BUTTON_ICON_NAMES` — same paths, no second inventory.

Host alone is **md**. Import `@eevenkoto/css/icon.css` (Button stories that show icons need it too).

## Why to use

Chrome needs the same glyphs in Button, adornments, and product UI without each consumer pasting SVG path strings. Icon is the shared renderer (size ladder + `currentColor`); the name inventory stays in core tokens so the catalog has one source of truth.

## Glyph tokens

| Export | Role |
| --- | --- |
| `ICON_NAMES` | Ordered inventory |
| `iconPaths` | `Record<IconName, string>` (16×16 `d`) |
| `BUTTON_ICON_NAMES` | Subset Button may use |
| `IconName` / `ButtonIconName` | Derived types |

```ts
import { ICON_NAMES, iconPaths, BUTTON_ICON_NAMES } from '@eevenkoto/core';
```

## Sizes

Shared **`sm | md | lg`** → `--eevenkoto-space-3` / `4` / `6`. Inside Button, CSS overrides to `1em` so the glyph tracks control type size.

<Canvas of={IconStories.Sizes} />

## Adding a glyph

1. Append the kebab-case name to **`ICON_NAMES`** in `packages/core/src/tokens/icons.ts`.
2. Add the matching path to **`iconPaths`**.
3. Optionally add it to **`BUTTON_ICON_NAMES`** after design review (keep Button sparse).
4. Rebuild `@eevenkoto/core`. The Tokens catalog updates automatically.

## API reference

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `name` | `IconName` | — | From token `ICON_NAMES`. |
| `size` | `'sm' \| 'md' \| 'lg'` | `'md'` | Size ladder. |
| `label` | `string` | — | Accessible name; omit when decorative. |
