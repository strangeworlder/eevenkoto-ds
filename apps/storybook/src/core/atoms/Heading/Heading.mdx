# Heading

Heading establishes page and section structure with a **multi-axis** six-level system: size, weight, family, case, posture, spacing, and light structural rules — not six pure size steps.

<Canvas of={HeadingStories.Default} />

```html
<h2 class="eevenkoto-heading">
  Section title
</h2>
```

Minimum hand-authored markup is the host class on the matching tag. Level comes from the element (`:where(h2).eevenkoto-heading`); framework helpers still emit explicit `--N` / tone classes.

### Playground

<Controls of={HeadingStories.Default} />

## Why multi-axis

A pure geometric scale makes H6 smaller than body or H1 absurdly large. Group levels into three visual tiers and split them with other axes:

| Visual tier | Levels | Differentiation |
| --- | --- | --- |
| **Macro** | H1, H2 | Outfit serif, distinct size jump, bottom rule, generous space-before |
| **Meso** | H3, H4 | H3 Outfit serif (`heading-3`); H4 Inter sans semibold (`heading-4`); no tint bands |
| **Micro / Statblock** | H5, H6 | H5 small-caps (`heading-5`) on sunken section band; H6 bold italic (`heading-6` = `body-md`) or run-in |

<Canvas of={HeadingStories.AllLevels} />

## Why to use

Pages need a scannable outline readers and assistive tech can trust. Heading gives six structured levels — size, weight, family, case, posture, and light rules — so titles stay consistent without faking hierarchy with bold Paragraphs or skipped levels for looks alone.

## When to use

Use Heading for page titles and section labels. One `h1` per view; nest levels without skipping for style alone.

### Minimum class & tag inference

| Markup | Level look |
| --- | --- |
| `<h1 class="eevenkoto-heading">` | H1 |
| `<h2 class="eevenkoto-heading">` | H2 |
| … through `<h6 class="eevenkoto-heading">` | H6 |
| `<h1 class="eevenkoto-heading eevenkoto-heading--3">` | **H3** (modifier overrides the tag) |
| Bare `<h1>` outside Prose | Not styled by the DS |

Tag maps use `:where(hN)` so specificity stays low and `--M` modifiers win by source order. For CMS / markdown HTML without classes, wrap in [Prose](?path=/docs/core-molecules-prose--docs).

## Key modifiers

### level

| Value | Element | Size token | Line-height | Family | Weight / posture | Color / anchor |
| --- | --- | --- | --- | --- | --- | --- |
| `1` | `h1` | `heading-1` | `snug` (`1.25`) | serif | bold | `content-primary` + strong bottom rule |
| `2` | `h2` | `heading-2` | `snug` (`1.25`) | serif | bold | `content-accent` (parchment in light, gold in dark) + subtle rule |
| `3` | `h3` | `heading-3` | `snug` (`1.25`) | serif | bold | `content-primary` |
| `4` | `h4` | `heading-4` | `body` (`1.5`) | sans | semibold | `content-accent` (parchment in light, gold in dark) |
| `5` | `h5` | `heading-5` | `body` (`1.5`) | sans | bold + small caps | `content-primary` on sunken band; bleeds by pad-inline (`margin ±X`, `width: 100% + 2X`) |
| `6` | `h6` | `heading-6` (= body-md) | `body` (`1.5`) | sans | bold italic | `content-accent` (parchment in light, gold in dark); optional run-in |
| `2`–`6` + `runIn` | `h2`–`h6` | level scale (unless a parent remaps) | level default | level default | inline-block + `. ` suffix | Drops block rules, padding, and sunken bleed band; Statblock/Spellblock remap to micro H6 look |

### tone

| Value | Content color |
| --- | --- |
| `primary` | `--eevenkoto-color-content-primary` |
| `secondary` | `--eevenkoto-color-content-secondary` |

<Canvas of={HeadingStories.Secondary} />

### runIn (H2–H6)

Flows the heading into the following `.eevenkoto-paragraph` (or bare `<p>` inside Prose) and appends a period suffix. Supported on levels **2** through **6** (`HEADING_RUN_IN_LEVELS`).

Supporting levels 2–6 lets embedded Statblocks and Spellblocks keep a contiguous heading outline (`nameLevel` + 1 or + 2) without skipping levels. Inline run-ins automatically strip macro bottom rules, padding, and H5's sunken bleed band.

<Canvas of={HeadingStories.RunIn} />

```html
<h6 class="eevenkoto-heading eevenkoto-heading--6 eevenkoto-heading--run-in">Safety protocol</h6>
<p class="eevenkoto-paragraph eevenkoto-paragraph--md eevenkoto-paragraph--primary">
  Always inspect the valve before engaging the primary circuit.
</p>
```

## Accessibility & flow

- Preserve logical heading order for screen readers.
- Headings use `break-after: avoid` / `break-inside: avoid` so print/PDF flows keep titles with following copy. Direct-child `h1` / `h2` of Prose also `column-span: all` in print (see [Print columns](?path=/docs/foundations-print-columns--docs)).
- Run-in keeps a real heading element (`h2`–`h6`) — do not demote it to a `<span>` for styling. Pick the level the outline needs.

## API reference

| Prop | Type | Default | Description |
| --- | --- | --- | --- |
| `level` | `1 \| 2 \| 3 \| 4 \| 5 \| 6` | `2` | Semantic heading level (`h1`–`h6`). |
| `text` | `string` | — | Heading copy (Astro also accepts the default slot). |
| `tone` | `'primary' \| 'secondary'` | `'primary'` | Content color tone. |
| `runIn` | `boolean` | `false` | Levels `2`–`6`: flows the heading inline into the following Paragraph. |
| `id` | `string` | — | Element `id` for anchor jumps and `aria-labelledby` (React, Vue, and Astro HTML attributes). |

| --- | --- |

| `--eevenkoto-heading-letter-spacing` | Tracking |
| `--eevenkoto-heading-line-height` | Line height |
| `--eevenkoto-heading-margin-block` | Block margin |
| `--eevenkoto-heading-padding` | Block/inline padding |
| `--eevenkoto-heading-pad-inline` / `--eevenkoto-heading-bleed` | Inline padding and negative bleed |
| `--eevenkoto-heading-background` | Heading plate background |
| `--eevenkoto-heading-radius` | Plate corner radius |
| `--eevenkoto-heading-border-block-end` | Macro underline rule (`h1` / `h2`) |
