## Caption vs Paragraph

| Need | Use |
| --- | --- |
| Multi-sentence body or supporting prose | **[Paragraph](?path=/docs/core-atoms-paragraph--docs)** |
| Timestamp, status line, or short helper under a control | **Caption** |
| De-emphasize a full paragraph (still body copy) | Paragraph `tone="secondary"` (`content-secondary`) |
| Quiet metadata ink | Caption default (`content-tertiary`) — quieter than Paragraph secondary |

Agents: if the string is a sentence people read as content, use Paragraph. If it is a label-adjacent hint, timestamp, or chrome metadata, use Caption.

## Why to use

Captions keep timestamps, helper hints, and field metadata visually quieter than body copy — smaller type and tertiary ink — without inventing a one-off rem or gray.

## When to use

Use Caption under form fields, on cards, or beside status metadata. Prefer Paragraph for multi-sentence prose and Heading for titles.

## Key modifiers

### tone

| Value | Default | Content color |
| --- | --- | --- |
| `secondary` | Yes | `--eevenkoto-color-content-tertiary` (metadata quiet) |
| `primary` | No | `--eevenkoto-color-content-primary` |

Caption’s default “secondary” tone is **not** the same token as Paragraph `--secondary`. Paragraph secondary uses `content-secondary`; Caption secondary uses quieter `content-tertiary`.
